# 九向转头、眼神与头身跟随

[返回目录](../README.md)

## 两种失败：拉扁与平移

用整体横向缩放模拟转头，容易同时压缩脸宽、眼距和下巴，让脸变扁。为了避免缩放而只移动整张头部，又会像贴纸横移。

小幅转头需要相对运动：脸轮廓略变，五官、鼻嘴、耳朵、前后头发产生不同幅度的位移和遮挡。**整体头部运动与局部透视形变应分开绑定。**

一种组织方法：

```text
头部父控制（整体朝向）
├─ 脸轮廓
├─ 五官
│  ├─ 左眼 / 右眼
│  ├─ 左眉 / 右眉
│  └─ 鼻 / 嘴
├─ 左耳 / 右耳
├─ 前发 / 侧发
└─ 后发 / 马尾
颈部过渡控制 → 领口固定挂点
```

这是组织建议，不是强制层级。实际父子关系还要考虑绘制顺序、参数组合和已存在的变形器。

## 九向指九个组合姿态，不是九条旋转轴

先建立 X、Y 各三个关键值，再检查九个组合，尤其四个对角线。官方的 [X/Y 关键形教程](https://docs.live2d.com/en/cubism-editor-manual/keyform-xydirection/)是基础入口。

第一阶段日常待机采用较克制的头部参数范围，曾使用 X ±7、Y ±5。它们是本模型参数单位，不能直接解释成真实三维角度，也不能原样套在另一张脸上。

检查时固定相机和比例，观察脸宽、眼距、鼻嘴关系、耳发遮挡及颈部挂点。端点正确不代表中间插值正确；在相邻关键形之间继续抽样。

## 小幅九向与明显撇脸分开制作

部件分离只是基础，不保证任意角度都像参考。后续暗夜夸奖的一版侧脸虽然没有新增异常翻折，仍被视觉验收否定。叠加旧朝向、专用转脸和眼部压缩，会放大不自然的形变。

该轮后来使用正面、中间与最终撇脸的确认原画，在同一原生模型中制作独立 UV、匹配网格和可见性交接。对齐眼鼻嘴、轮廓、发夹与颈部后，继续检查中间插值和闭眼。它有额外素材与资源成本，不能替代所有小幅转头；完整过程见[侧脸案例](../cases/04-reference-angle-head.md)。

## 水润眼睛不能只靠加亮

甜美感与眼裂曲线、虹膜露出比例、外眼角、睫毛长度、眉眼距离共同有关。把虹膜压暗、睫毛加粗，即使高光更亮，也可能更严肃。

我们的顺序：

1. 同角度对齐底图，恢复眼型与睫毛末端；
2. 保留虹膜明暗层次，控制高光大小；
3. 左右眼分别校准，不默认镜像就是正确；
4. 表情、视线、眨眼组合检查。

崇拜中的星星眼还要检查“眼睛睁大”是否来自眼裂和上下眼睑，而非把整块皮肤拉大。

## 视线与眨眼

眼皮/睫毛负责开合，虹膜负责视线，眼白负责可见范围。父子层级本身不会产生剪贴，必须配置 [Clipping ID](https://docs.live2d.com/en/cubism-editor-manual/clipping-mask/) 或相应宿主遮罩。

本项目历史待机有六档眼睑素材，通过原生透明度关键形混合；它是阶段性实现选择，不等于任意形态的连续眼睑曲线。是否采用多档素材或连续网格，应按美术质量、预算与目标宿主判断。

验收最少覆盖开眼 0、0.25、0.5、0.75、1，叠加中心和边界视线。参数存在于列表中，还需要读取目标 Drawable 的响应。

视线向下不等于降低眼开度。暗夜翻书要表达轻微仰头、向下看书的冷淡感，一味压低眼睑反而像困倦。头部朝向、虹膜位置与眼睑形状应分别设计。专用表情若仅有开眼素材，应明确其短暂阶段的眨眼限制，不借用旧眼图冒充完整支持。

## 让眼、头、身有不同响应

鼠标坐标归一化后限制在单位圆附近，避免角落输入把 X/Y 同时推得过大。眼睛先响应，头部稍慢，身体更慢；本项目曾以约 85 / 230 / 420 ms 作为调试起点，不是固定标准。

帧率无关的一阶跟随可用：

```js
const a = 1 - Math.exp(-dt / tau);
value += (target - value) * a;
```

发根保持稳定，发尾使用有阻尼的惯性响应。暂停、切到后台或窗口恢复时处理残余速度，避免一次大时间步把头发甩飞。不要用全局动作加速影响这一套自然响应。

可运行的跟随示例见 [examples](../examples/README.md)。
