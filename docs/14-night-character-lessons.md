# 暗夜独立角色：新增经验与旧结论修订

[返回目录](../README.md) · [证据与版本](../references/night-character-evidence.md)

本轮整理于 **2026-10-22**，覆盖暗夜独立待机、翻书、打招呼、夸奖，以及鼓励和失败的制作记录。它延续 AI 出图、脚本整理、官方原生导出和人的视觉确认流程。原模型与完整制作程序仍不公开；下文的历史数值不是公共 CI 可复算的模型结果。

## 哪些旧说法需要修改

早期单模型、换装和小幅转头的成果仍成立；问题是把阶段性选择写成了后续所有角色都应遵循的路线。

| 早期表述或做法 | 后续发现 | 修订后的适用范围 |
|---|---|---|
| 日常与暗夜统一换装、共享动作 | 用户把暗夜定义成独立性格与表演体系，甜美待机改几处参数无法还原冷艳底图 | 同一角色换造型可以共享；独立角色应重新评估脸部、参数和动作，业务意图仍可共用 |
| 尽量共享脸、头发和衣身 | 旧脸的拓扑和开眼形态约束了新五官 | 先保护已确认外观，再决定复用；不以复用率作为视觉验收目标 |
| 分开五官并增加透视形变能解决侧脸 | 一版侧脸数值检查通过，仍被用户指出脸被拉扯、眼型不像 | 小幅九向与明显撇脸分开处理；目标外观超出可接受形变时补对应角度原画 |
| 数值检查通过，再做少量视觉抽样 | 无新增翻折仍可能有重影、露底、错眼型和错误神态 | 数值、实际渲染、用户视觉确认各自记录，不能互相替代 |
| 关节有问题就重新做手臂结构 | 打招呼多次重做后比第一版更差 | 已确认的轨迹、比例、袖型先冻结，只修有证据的局部缺陷 |
| 动作回到默认参数就完成衔接 | 中途退出可能经过未制作的脸部组合 | 从当前状态按依赖顺序返回，检查退出路径中的每一采样帧 |
| 先检查参数全组合 | 部分专用素材只为受约束的动作区间制作 | 预先定义支持域，覆盖全部可达路径；域外输入必须被拒绝、排队或安全转换 |
| 一个最终导出可以沿用前一版检查 | 领口、脸层和纹理的最后修补也会改变结果 | 检查绑定到源工程、MOC、纹理、动作与控制器版本；新导出明确重验范围 |

## 1. 先区分换装、角色与业务意图

暗夜从“穿深色衣服的同一套表演”变成了“外表冷淡、内在关心人的傲娇角色”。这不是把日常挥手整体减速就能完成的变化。先写清是谁在表达、对谁表达、发生了什么：

| 意图 | 这轮设计中的暗夜表达 | 容易混淆的表达 |
|---|---|---|
| 打招呼 | 先注意到对方，抬手时移开视线 | 全程热情招手 |
| 夸奖用户 | 看向对方、浅笑点头、胸侧轻竖拇指，再撇脸 | 一个没有认可意味的摊掌 |
| 鼓励用户 | 克制地关心，给出可读的支持手势 | 夸耀自己的能力 |
| 自己成功 | “这种事本小姐轻松做到”的得意 | 崇拜用户 |
| 自己失败被发现 | 懊恼、咬牙、掩饰失态 | 安慰用户失败 |

表格记录设计语义，不表示五项都已完成绑定或产品接入。尤其成功分镜在本轮证据快照中仍是候选。

建议把业务事件映射为语义意图，再由角色选择动作；发型、服装、饰品保持独立配置。是否用一个或多个 MOC 是实现决策，不是角色语义本身。独立角色也可以共享输入归一化、时钟和加载机制，而不共享全部面部曲线。

**待机是持续状态。** 九向跟随、自然眨眼、呼吸与发尾响应在其中持续工作。有限动作暂时接管相关参数，退出完成后再恢复这些职责；随机空闲动作和持续输入也必须受状态机约束。

## 2. 原画一致性要在绑定前建立

独立暗夜脸的第一步是静态回合成：统一原画坐标，不逐个缩放五官，先证明可见部分没有被重画或移动。这一步当时没有旧网格、旧变形器或旧关键形参与，但也**没有完成眨眼、视线或转头**。

之后才补完整虹膜、眼白、闭眼、刘海后的眉毛、眼部下方皮肤和转头会露出的区域。新像素只填需要出现的部分，不能为了补全重新生成整张已确认的脸。

分镜从同一待机身体生成，固定相机、肩颈、腰线、书和腿部。一个更漂亮但身体机位不同的分镜，会把后续绑定变成强行纠正透视。检查头部时也应保留全身上下文，避免近景正确而接到领口后比例失真。

## 3. 撇脸需要对应角度，不等于必须做三个完整模型

夸奖动作曾叠加原有头部朝向、专用转脸和眼部压缩，数值没有新增异常翻折，观感仍失败。后续使用确认的**正面、转到一半、最终撇脸**三张头部原画，在同一原生模型中安排各角度的 UV、网格与透明度关键形。

关键不只是增加三张图，而是配准脸轮廓、眼角、虹膜、鼻嘴、发夹与颈部，再设计角度间的形变、可见性和遮挡。否则会从“拉脸”变成“双眼重影”。本项目还需要在分段映射边界细分网格，避免一块三角形跨过两套不连续的映射。

这一路线增加素材、图集、关键形与检查成本。小幅九向仍可使用常规变形器；没有理由把所有转头都改成多角度图。具体失败与修订见[侧脸案例](../cases/04-reference-angle-head.md)。

官方 [3D 旋转表现](https://docs.live2d.com/en/cubism-editor-manual/apply-3d-rotation-expression/)与 [Blend Shape](https://docs.live2d.com/en/cubism-editor-manual/blend-shape/)也是可评估的工具，但本轮将它们列为调研路线，没有据此宣称已替代上述制作方案。

## 4. 冷淡表情不是一味闭小眼睛

翻书阶段“垂眸”曾做得像困倦。后续明确目标为轻微仰头、视线向下看书，而不是低头加半闭眼。应分别控制头部姿态、虹膜视线、眼睑开度与嘴形，并锁定需要保持的身体视角。

冷艳笑也不是通用的两侧嘴角上扬。夸奖的唇线先按确认底图校准，之后修侧脸时保护这条嘴形。动作中的认可要在实际全身显示尺寸可读，不能只在放大的单帧里勉强看出。

## 5. 局部修复优先保护已确认运动

打招呼的肘部说明：技术上更复杂的重做，不一定视觉更好。用户最后要求以第一版为基线，只去掉尖角、重叠和接缝。随后检查手部路径、非目标部件和保留的袖料，防止悄悄改回另一种动作。

对明显旋转的手掌或前臂，要检查中间插值是否缩短或剪切。围绕稳定关节的旋转与局部衣料变形可以分开处理；不能只证明端点或腕点一致。持书手还要保护拇指、腕口、书缘的组合关系，避免替换整本书时把托书手一起抹掉。详见[肘部案例](../cases/05-elbow-minimal-repair.md)。

## 6. 返回待机是一条有约束的路径

部分专用侧脸只有在对应表情已经建立时才有效。假设某模型要求 `turn > 0` 时 `face >= 0.45`，把两者同时线性减到零，会在返回途中违反约束，即使终点完全正确。

这轮失败动作采用的顺序是：保留所需表情，先把脸转回支持的朝向，再淡出表情，最后交回头身与眼神跟随。手臂是否能并行返回，要单独验证。这个阈值是项目契约，不是 Cubism 的通用限制。

实现与验收应包括：

- 在动作任意可中断位置捕获当前参数，从该状态返回，不能跳到固定“退出起点”。
- 检查正常播放、提前退出、重复触发与切换动作的完整可达路径。
- 眨眼、物理和跟随加入后再检查；专用惊讶瞬间若只有开眼素材，应明确限制自然眨眼，不能称为完整眨眼支持。
- 在制作前写支持域和域外策略；不能看到失败组合后，才把它从测试中删掉。

无模型依赖的[返回路径教学示例](../examples/ordered-return.mjs)演示为什么统一淡出会越界，以及分阶段返回如何维持一个明确的约束；它不包含项目控制器，也不证明真实模型没有视觉问题。

## 7. 检查报告也要接受修正

“坐标误差很小”只说明配准；“无新增翻折”只说明检查范围内的几何条件；“截图像底图”还不能说明中途退出正确。新版本必须分别列出原生导出、Core 采样、像素与遮罩检查、编辑器截图、浏览器动态、用户确认和产品同步状态。

旧模型也可能已有三角形异常。只有在声明的对应姿态、相同顶点和透明度容差下证明一致，才可标成继承问题；仍要列出，不能跳过整类旧网格。几何覆盖还需结合 UV、纹理 Alpha 和实际合成检查。抽样无孔洞不等于连续全域无孔洞。

浏览器检查受阻时，保存原生实拍截图并标记动态未验证；AI 分镜不能代替原生结果。命名为 `final` 的文件也不自动成为交付基线，应由清单和哈希确定。详细方法见[验证章节](10-validation.md)。

这些修订的目的，是让 AI 更早识别“应保留什么、应重画什么、哪些证据还不足”，而不是把一次局部成功升级成通用自动绑定承诺。
