# AI 工具与成熟方案调研

[返回目录](../README.md)

这篇负责工具选型。我们实际怎样用 AI 贯穿设计、出图、绑定、动作、接入与验证，见[全流程制作实录](00-ai-pipeline.md)。

以下把本项目实际采用的方法与只读调研区分开。外部项目页面于 2026-10-20 复核；本仓库没有替这些工具提供兼容认证。

## 已采用的路线

AI Agent 负责从设计探索到工程实现的执行：调用图像工具生成和精修素材，编写坐标配准、图集、绑定数据和源工程处理程序，编排动作，实现 Web 宿主，再写回归检查和制作动态对照。原生几何和关键形变化通过官方 Editor 保存导出，人确认方向与可见效果。

好处是任务边界清楚：生成失败可以只弃用局部，数值脚本可以确认没碰到其他区域。代价是仍需要美术判断和原生工程知识。

## 调研过的路线

| 路线与一手来源 | 能参考什么 | 本项目证据与限制 |
|---|---|---|
| [See-through](https://github.com/shitagaki-lab/see-through) | 单图语义分层、隐藏部分补全、PSD 输出 | 仅调研。作者明确分层不等于完整 Live2D 绑定；细粒度艺术拆分还需设计 |
| [PSD2Live](https://github.com/tsunehimatoi/psd2live) | 作者声明的 PSD 自动绑定、网格/变形器、编辑与导出流程 | 仅调研。没有在本项目完成完整资产往返与所有动作兼容验证 |
| [AutoLive2d](https://github.com/Fenglin-Maple/AutoLive2d) | AI 辅助角色和表情的实践流程 | 仅调研。学习完整脸部上下文与局部素材的协调，不据网页动画推断官方原生格式兼容 |
| [Cubism 官方 Web Samples](https://github.com/Live2D/CubismWebSamples) | 模型加载、动作、表情、交互的参考实现 | 阅读机制与文件组织；示例素材和 SDK 使用遵守各自许可 |
| Cubism 自带关键形、变形器、物理等流程 | 从已分层素材建立可解释的控制结构 | 本项目采用原生编辑与导出；自动工具结果仍需逐姿态验收 |

See-through 官方当前说明有不同显存优化路线。具体硬件需求随版本、分辨率和精度变化，应按官方说明实测；不引用旧机器枚举结果推断读者能否运行。

历史还关注过通用图像分层、单图到可编辑角色研究、Alpha 编辑 API 等方向。它们可进入后续调研清单，但没有纳入本仓库的已验证交付链，不把论文效果、作者演示或 Alpha 功能写成项目已完成能力。

## 怎么选择，避免工具清单变成承诺

先给一个眼睛或袖口的小样，检查：

1. 回合成是否保持已确认神态；
2. PSD/CMO3 是否真的可编辑，还是只导出了外观近似物；
3. 参数是否影响当前可见部件；
4. 官方 Editor 能否打开、保存、导出；
5. 目标宿主的闭眼、转头、遮挡与原画是否一致；
6. 成功后能否只修改一个部位而不破坏其他动作。

把耗时、返工次数、失败组合和版本一起记录，再决定是否扩大使用。

## 给 AI 的任务应可验收

不说“把模型做自然”。改成：

> 对齐已确认底图中画面右眼的眼裂、外眼角与眉眼距离。先读取相关网格、参数和遮罩关系。只改指定表情权重下的目标关键形；保留待机、闭眼与其他动作。交付同角度全开/半闭/闭眼、九向边界和进出动作对照，并报告非目标部件差异。

AI 可以帮助缩小搜索范围，不能替代用户对画风与神态的最终判断。
