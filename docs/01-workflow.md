# 制作流程与交付边界

[返回目录](../README.md)

## 我们最早混淆了什么

一张表情图在网页里切换、一个二维网格在 Canvas 上变形、一个 Cubism 模型在 Core 中响应参数，三者都能产生动画，但交付能力不同。尤其不能把“新眼图能显示，旧眼图负责闭眼”描述成新眼睛已经独立绑定。

项目早期对思考眼睛做过参数探测：改变眼开合与视线，新眼图没有原生顶点或透明度响应，旧眼层却有响应。页面仍能表现眨眼，是运行时在换图。这个结果改变了后续验收方式：**必须检查画面中实际使用的对象。**

## 六个关口

| 关口 | 交付物 | 继续工作的条件 |
|---|---|---|
| 底图 | 确认版全身、脸与重要手势 | 脸型、微笑、眼型、肤色明确 |
| 素材 | 图层、遮挡补全、回合成图 | 拆开再合回去，已确认的可见像素与关系不漂移 |
| 绑定 | 网格、变形器、参数、关键形 | 单参数有效；目标以外部位不被意外牵动 |
| 动作 | 进入、保持、返回和中途切换 | 表情可读、接触稳定、回到待机基线 |
| 接入 | 宿主输入、外观、渲染、资源加载 | 用实际产品显示尺寸验证，不只看独立大预览 |
| 交付 | 源工程、运行文件族、控制契约、校验记录 | 重开可编辑，导出可加载，接入效果可复现 |

## 别把每轮修正变成整张重做

确认过的脸型、手指、服装纹理和动作节奏应当成为受保护的基线。每次写清：

- 当前唯一要解决的可见问题。
- 允许修改的图层、参数或图集区域。
- 必须保持不变的内容。
- 用什么姿态、时间点、背景验收。

例如“去掉袖口绿块”只要求修连续暗色布料和边缘，不能顺带重画手指。AI 生成结果若改善了袖料但改变了手型，只取可用局部。

## 决策不是单向的

我们曾尝试只平移耳前发束上端，让耳朵露得更多；结果发根出现折角，所以撤回。之后扩大渐变权重、降低最大位移，才改善连续性。

保留“尝试过但不采用”的记录，有助于后续避免重复走弯路。回滚要通过源资产或哈希验证，而不是凭记忆认为已恢复。

## 最小可行制作顺序

先完成默认造型的一套稳定待机，包含闭眼、九向头部和头身跟随，再增加一个代表性动作。之后再扩展全动作、统一外观和主题转场。这样可以更早发现参数职责、遮罩和源素材不足。
