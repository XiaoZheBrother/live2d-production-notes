# AI Builder 起步路线：先跑通一个最小闭环

[返回目录](../README.md)

目标是让你用自己的角色，走一遍“AI 出图 → 可编辑素材 → 原生参数 → 实际网页”的制作链。先选一个表情和一个动作，把后续九动作和换装需要的结构预留出来。

## 准备输入

- 有权使用和编辑的角色参考图，或由你确认的 AI 设计稿；
- 能读取本地文件、编写并执行程序的 AI Agent；
- 参考图驱动的图像生成/编辑工具；
- 官方 Cubism 编辑与目标运行环境；
- 用于脚本和版本管理的 Node.js、Python、Git。

本仓库可以直接运行的是 `examples/` 与文档检查。角色原画、完整绑定程序和产品运行器需要在你的项目中准备，不能仅克隆本仓库就得到 OC 娘模型。

## 第一步：让 AI 给出制作契约

先告诉 Agent：角色气质、必须保留的五官、目标动作、显示尺寸、是否需要换装，以及最终交付是原生 Cubism 加 Web 交互。

先区分“同一角色换衣服”和“独立性格、五官与表演的新角色”。前者重点是全动作外观覆盖，后者可能需要新脸与新动作；不要为了维持单模型而牺牲已确认底图。业务意图可以共享，表演曲线不必相同。

让它写一页清单：输入素材、可动部件、参数职责、导出文件、宿主依赖、验收方式。使用 [Agent 任务模板](../templates/ai-task.md)。

**通过条件：** 你能明确区分概念图、分层素材、模型和网页效果。

## 第二步：先批准一张稳定底图

让 AI 给少量有明显差异的候选，选择一个方向后固定参考。每轮只改指定部位；完整脸部上下文用于保持神态，局部修补用于保护既有像素。

**通过条件：** 全身、脸和手的静态效果都接受；透明通道实际存在；裁切没有缺发尾或鞋尖。

## 第三步：只绑定最能暴露问题的部分

从小幅九向头部、独立视线和眨眼开始，要求 AI 检查眼白遮罩、耳发遮挡和颈部挂点。把脚本与数据保存在自己的项目里，保留每轮基线。

**通过条件：** 当前可见部件对参数有真实响应；同角度看脸型仍然一致，四个对角线不露底。

## 第四步：加一个动作，验证进出待机

选择挥手或思考。前者容易暴露腕口与肩袖问题，后者容易暴露脸型、肤色和表情衔接问题。让 AI 建立进入、主姿态和返回三段，并保护自然眨眼和发尾。

**通过条件：** 不只主姿态好看，准备和收尾也连续；从允许的任意中断位置能沿有效路径回到待机；恢复跟随不跳变；低帧率不导致动作时间不断变长。检查不能仅停在返回终点，见[有约束返回示例](../examples/ordered-return.mjs)。

## 第五步：导出并接入真实尺寸的网页

让 AI 准备官方 Editor 的保存与导出步骤，再检查导出文件族。鼠标输入、物理、外观和转场属于宿主契约，需要明确接线。

网页要提供全身与近景、动作暂停/重播、背景切换。让前后版本锁在同一个动作时间比较。

**通过条件：** 官方导出的模型能在目标 Core 加载，页面显示尺寸下清晰，实际输入与预览一致。

## 第六步：再扩展动作与换装

先列全部动作所用部件，再制作新服装或发型。每次增加特殊姿态，都更新外观覆盖表和检查矩阵。把“动作状态”和“外观状态”保持独立。

**通过条件：** 只换一次，全动作都更新；快速反向切换不被旧请求覆盖，加载失败保留旧外观。

## 把反馈变成下一轮任务

| 模糊反馈 | 更容易执行的反馈 |
|---|---|
| 不够可爱 | 同角度比较，画面右眼开度偏小、外眼角过陡 |
| 手有点怪 | 抬手主姿态的掌心被横向压缩，腕点保持不动 |
| 衣服像贴上去 | 肩袖明暗断裂，抬臂时衣身没有轻微跟随 |
| 动作太慢 | 压缩准备和返回，保留主表情停留与眨眼 |
| 暗夜没换干净 | 翻页时画面右侧手腕仍露出日常袖口 |

不必一开始就知道精确根因；提供动作、时间点、方向和截图，让 Agent 从证据定位。修复后的验收仍回到同一姿态。

## 让 Agent 每轮交付什么

一份可回退修改、一个能看结果的预览、实际执行的检查记录、明确的下一步限制。把这些积累成你自己的制作笔记，后续换服装或升级模型才不会从头摸索。

特别区分静态回合成、独立绑定、原生导出、动态检查、用户确认与产品同步；前一阶段完成不会自动证明后一阶段。新近反例与修正见[暗夜独立角色经验](14-night-character-lessons.md)。
