## 新功能与当前边界

暗夜目前采用稳定待机与八个独立动作：翻书、打招呼、思考、鼓励、倾听、失败、害羞、成功。夸奖退出交付清单，由成功承担最终选择的表现。日常仍使用既有原生主模型；暗夜按动作加载独立原生模型，复用宿主的语义动作 ID、鼠标输入与主题转场。

## 大幅转头失败之后真正学到了什么

关键缺失是**同一发束在各视角的身份和遮挡关系**，并非只缺一种插值函数。自动对应可能匹配到相邻的相似发纹；逐行取 Alpha 最左/最右点会跳过卷发孔隙；镜像单侧马尾会把内侧碎发变成外侧尖齿；扩大平滑能消翻折，却也抹平正确五官。

See-through 提供语义层和补全候选；RAFT 提供对应候选；固定拓扑、局部保形与旋转变形器提供几何控制。它们各自解决一部分问题，没有一种在这轮完成了完整头部的自动保真转动。ARAP 风格试验不是论文算法的完整复现；失败不否定整个方法类别。

逐束试验要求先检查根、尖、内外边缘、中心线、反面与前后层归属。移动发束后，脸皮、耳边、衣领里烘焙的旧发丝也要处理，否则“新增干净发层”会和旧残留重影。遮挡区切换仅在该表面确实不可见时成立，必须覆盖转出、返回与参与的物理/俯仰组合。局部为零不能证明全角色为零。

2026-10-30 用户决定暂停大幅转头，保留全部材料，恢复稳定待机，完成最后的倾听。这是交付范围的明确调整；不能把缩小幅度包装成原目标已解决。详见[大幅转头试验案例](../cases/07-large-turn-trials.md)。

## 材料、遮罩与关节的新增细节

- **颜色通道不画，不等于遮罩不参与。** 害羞预览曾因跳过透明度为零的专用 stencil 几何，造成颈发缺失。此结论针对该自定义渲染器的遮罩契约；不能改成所有 SDK 都要忽略遮罩透明度。
- **藏手用局部遮挡，不用缩手。** 成功的 v5 只放大抱胸终点，起手仍小；后续保持手的尺寸，用局部袖料遮住指尖、留下腕与掌根。整块袖料又造成矩形边界，最终限制在手部剪贴区域。
- **几何与 UV 都要保护。** 空白面皮若未配准，会把耳朵或旧发丝采到脸上；图集边界的 clamp-to-edge 也可能拉出不透明边行。
- **归属先于补画。** 透明像素的隐藏 RGB 不等于有效隐藏区域；补图应有明确曝光范围，而不是无差别覆盖已确认的脸和发型。
- **源姿态先自然。** 待机膝盖内扣属于立绘/站姿设计检查，不能靠左右摇摆掩盖。候选腿部改变后仍需重新核对裙摆、双脚接地与所有动作。

## 从静态验模扩展到模型生命周期

原先单模型轮播未覆盖“日常常驻 + 当前暗夜 + 待加载暗夜”三实例并存。固定版本 Core 的 asm.js 堆扩容复制后，旧 TypedArray 保持非零长度，却读写旧内存。于是动作层隐藏了待机脸，动作脸参数却没有真正生效，画面丢脸；鼠标参数也写不进当前引擎。

项目采用分配后统一刷新存活模型视图，并保留渲染闭包引用的容器身份；分配失败也可能增长堆，不能只在成功返回时刷新。它用了固定版本内部构造器与指针，升级必须重新验证。预留内存曾缓解早期多视图问题，但不能作为任意模型数量的保证。公开仓库只给出[无 SDK 的原理示例](../examples/heap-views.mjs)，不分发该项目适配器。详见[生命周期案例](../cases/08-live-model-heap.md)。

另一问题是动作重播先发出 idle，再进入同一动作；主题包装层曾清掉意图而没有恢复。新的动作开始通知必须重新同步意图，同时过滤隐藏主题的回调。请求版本解决的是异步资源提交，不能单独解决语义状态。见[主题交接案例](../cases/09-theme-action-handoff.md)。

## 新的验收维度

1. 保留活跃旧模型，加载新实例，并证明确实触发了目标内存增长路径；对旧、新模型都探测顶点与表情透明度响应。
2. 每个动作在进入、中段、退出切换两种主题，再测烟雾/显现阶段连续反向、重播、首次加载未完成和过期加载返回。
3. 返回待机后实际移动鼠标，检查头、身、眼参数和渲染，不只看页面写着 idle。
4. 对隐藏补片加可见的阳性对照，报告完整范围、前后遮挡物及未测组合。
5. 正常/半速录像报告解码时长、帧数与间隔。约 9.5 fps 的片段不能证明 30/60 fps 顺滑；浏览器候选发层叠在原生身体上也不是新 MOC 录像。

历史本地回归记录为 57/57 真实渲染场景、156 项测试通过；这是固定版本和有限场景的证据。此次知识库检查只重跑公开教学示例与文档/skill 校验，没有重新执行这 57 个私有角色场景。

## 可以做成怎样的 skill

[live2d-production](../skills/live2d-production/SKILL.md) 是本轮新增的可携带工作流：识别现有资产与批准基线，选择素材/绑定/动作/宿主修复路径，执行有限试验，按证据决定继续、回退或交付。提供只读运行包检查器、分层曝光检查、动作退出与主题矩阵；不携带角色资产、Core、私有构建器或直接写 MOC 的编译器。

流程按原画、拆层、绑定、动作、宿主与交付分阶段组织，先核对环境和已确认角色约束，再做正常/半速自查与用户视觉验收。不能为适配工具而擅自改变已确认的发型、身体机位或交付格式。

因此，本 skill 能指导并辅助已有工具完成制作，**当前不是通用的一键全身自动绑定器**。后续若要增加生成器，先为一束发或一个关节建立可复现的小样，再扩大能力声明。
