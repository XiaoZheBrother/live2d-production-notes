# 回归验证与同条件对照

[返回目录](../README.md)

## 两类证据要分开

数值检查能证明参数响应、顶点范围、文件相同或局部改动边界；不能证明“更可爱”“像底图”“接缝自然”。视觉对照能暴露神态问题，也不能单独证明未修改其他动作。

每次报告同时写：验证对象、版本、输入姿态、变化范围、结果与未覆盖内容。

## 最小矩阵

| 维度 | 取样建议 |
|---|---|
| 动作 | 待机、翻书、挥手、思考、鼓励、倾听、失落、害羞、崇拜 |
| 时间 | 进入、主姿态、变化最快处、回落、结束；缺陷发生帧额外加密 |
| 朝向 | X/Y 九向与中间值，尤其四角 |
| 眼睛 | 全开、半闭、闭合，中心和边界视线 |
| 外观 | 日常、暗夜，动作中切换 |
| 背景 | 浅色、深色、棋盘格或实际页面 |
| 输入 | 快速反向鼠标、暂停恢复、动作中断、主题连续切换 |

矩阵很大时，先跑便宜的数值全组合，再对风险姿态做视觉抽样。不能把抽样通过描述成所有连续状态的数学证明。

## 数值检查

- 所有顶点、参数为有限数值；
- 参数范围和默认值符合契约；
- UV、纹理引用和索引有效；
- 原本有效的三角形不新增异常翻折；排除本来就退化的三角形再比较；
- 仅局部修复时，非目标网格、图集区域和动作文件保持一致；
- 进入和返回端点恢复基线；
- 资源 SHA-256 与交付清单一致。

像素相同不等于 PNG 文件字节相同；重新编码 PNG 也会改变哈希。按目标分别做像素比较和文件哈希比较。

## 视觉对照

将前后版本锁在同一动作时刻、同一相机、同一头部/视线输入。全身看比例和动作意图，近景看接缝和五官。标注“画面右眼”或“角色右眼”，不要混用。

如果为降低负担只显示单版本，切换时保留当前姿态；同时显示多个版本则共用动作时钟。截图必须标明时间与版本。

## 在产品里再验一次

开发页和站内入口应使用同一渲染器与控制器，避免两套实现悄悄分叉。本地调试入口只在开发环境出现，生产构建要检查没有混入动作选择器、调试素材和测试入口。

浏览器无报错只说明没有捕获到该类错误，不是视觉通过。构建通过也不代表已经发布。把“本地同步”“正式导出”“线上部署”分别记录。
