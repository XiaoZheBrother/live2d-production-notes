# 回归验证与同条件对照

[返回目录](../README.md)

## 两类证据要分开

数值检查能证明参数响应、顶点范围、文件相同或局部改动边界；不能证明“更可爱”“像底图”“接缝自然”。视觉对照能暴露神态问题，也不能单独证明未修改其他动作。

每次报告同时写：验证对象、版本、输入姿态、变化范围、结果与未覆盖内容。

暗夜夸奖的历史侧脸 v5 就出现了“数值通过，用户拒绝”的结果。关键点配准误差不能称为视觉相似度；没有新增翻折，也不能证明没有重影、孔洞或错误神态。见[侧脸案例](../cases/04-reference-angle-head.md)。

## 最小矩阵

| 维度 | 取样建议 |
|---|---|
| 动作 | 待机、翻书、挥手、思考、鼓励、倾听、失落、害羞、崇拜 |
| 时间 | 进入、主姿态、变化最快处、回落、结束；缺陷发生帧额外加密 |
| 朝向 | X/Y 九向与中间值，尤其四角 |
| 眼睛 | 全开、半闭、闭合，中心和边界视线 |
| 外观 | 日常、暗夜，动作中切换 |
| 背景 | 浅色、深色、棋盘格或实际页面 |
| 输入 | 快速反向鼠标、暂停恢复、动作中断、主题连续切换 |

先声明模型支持的参数域，再检查该域内的端点、边界和中间值，以及控制器实际可达的组合。有些动作限定“先建立表情才能撇脸”，并不支持任意参数笛卡尔积。必须在实现前写出这种约束，并确认正常播放、所有允许的退出与重复触发都不越界；域外输入的拒绝或安全转换也要测试，不能事后删除失败组合。

在支持域内先跑数值采样，再对风险姿态做视觉对照。不能把抽样通过描述成所有连续状态的数学证明。

## 数值检查

- 所有顶点、参数为有限数值；
- 参数范围和默认值符合契约；
- UV、纹理引用和索引有效；
- 原本有效的三角形不新增异常翻折；已有异常与新增异常分别报告，不直接跳过旧网格；
- 仅局部修复时，非目标网格、图集区域和动作文件保持一致；
- 进入、返回端点恢复基线，正常与中途退出的每个采样帧保持支持域及接触约束；
- 资源 SHA-256 与交付清单一致。

像素相同不等于 PNG 文件字节相同；重新编码 PNG 也会改变哈希。按目标分别做像素比较和文件哈希比较。

## 旧缺陷与新回归怎样区分

将异常归为“继承基线”之前，必须固定对应版本与比较姿态，并验证相同三角形的三个顶点及透明度都在预先声明的容差内一致。不同默认参数或采样位置会使比较失真。若需要匹配导出关键值，记录候选值和严格容差，不用宽泛的近似匹配掩盖新变化。

已有缺陷仍要列出及说明可见性风险。不能跳过所有旧网格、提高翻折阈值，或把“继承缺陷”改写成“模型没有缺陷”。Drawable 透明度也不等于最终像素可见度，后者还受纹理 Alpha、蒙版、绘制顺序与合成影响。

## 无翻折不等于没有接缝孔洞

对颈部、领口、肩袖等风险区域，检查实际网格覆盖，并通过 UV 采样纹理 Alpha；蒙版和叠层还要在渲染结果中确认。失败动作的一份历史报告检查了 46 个姿态、每姿态 437 个领口采样点，只能说明这些采样通过，不能证明其他位置和所有连续状态都没有孔洞。

对照时叠加自然眨眼、呼吸、发尾以及跟随恢复，不只跑动作曲线。动画中途退出后，最终参数回零不能排除途中出现过穿模。

## 样本数量必须带空间范围

头冠修补 v3 的 390 个 Alpha 样本全部通过，用户仍看到下方发际缺角：样本只检查源图 y=140～230，修复回接旧边界的问题却在 y=240～310。增加同一区域的姿态数，不能弥补空间范围遗漏。见[完整案例](../cases/06-crown-coverage-gap.md)。

覆盖报告至少记录：

- 原缺口、修复区、回接带、相邻外轮廓与保护区的源图坐标及映射方式；
- 目标轮廓来自哪份确认原画或独立标注，是否与实现共用同一份轮廓；
- 空间采样范围、分布、密度、姿态集合、Alpha 阈值与未覆盖区域；
- 应出现的纹理覆盖是否存在，以及补层是否盖住五官、带入背景或越出允许边界。

测试只从实现生成的补层反推目标区域，容易形成“实现验证自己”。即使扩大范围，有限采样也不能证明连续全域。保护区检查还要关注目标补层的贡献；最终像素本来就不透明的脸，不能只凭合成 Alpha 判断是否被头发误盖。

[空间采样教学示例](../examples/coverage-sampling.mjs)使用独立的几何目标与故意有缺口的候选，演示局部全过、扩大范围失败，以及过宽补层误盖保护区。它不加载角色纹理、网格或 Cubism，不能作为模型验收结果。

## 视觉对照

将前后版本锁在同一动作时刻、同一相机、同一头部/视线输入。全身看比例和动作意图，近景看接缝和五官。标注“画面右眼”或“角色右眼”，不要混用。

如果为降低负担只显示单版本，切换时保留当前姿态；同时显示多个版本则共用动作时钟。截图必须标明时间与版本。

## 在产品里再验一次

开发页和站内入口应使用同一渲染器与控制器，避免两套实现悄悄分叉。本地调试入口只在开发环境出现，生产构建要检查没有混入动作选择器、调试素材和测试入口。

浏览器无报错只说明没有捕获到该类错误，不是视觉通过。构建通过也不代表已经发布。把“本地同步”“正式导出”“线上部署”分别记录。

## 报告必须对应同一个交付版本

| 证据层 | 能说明什么 | 不能替代什么 |
|---|---|---|
| 素材与工程预检 | 引用、字段、配准和资源契约 | 官方成功载入与保存 |
| 官方保存与导出 | 该候选经过相应原生流程 | 所有参数都正确绑定 |
| 目标 Core 采样 | 实际 Drawable 的响应和检查范围内差异 | 神态及动作语义 |
| Alpha、遮罩与实际截图 | 相应姿态的覆盖和可见结果 | 全过程动态检查 |
| 浏览器动态 | 指定宿主、输入、版本下的效果 | 用户视觉接受与产品同步 |
| 用户确认与产品验证 | 指定版本被接受、在指定环境接入 | 未制作的其他动作或线上发布 |

固定源工程、MOC、纹理、动作与控制器版本，再关联每项报告。最终修补后未重跑的检查明确写“仅前一候选”；浏览器受阻写“未验证”，不用 AI 分镜代替原生截图。公开 CI 只验证本仓库文档与独立示例，不执行私有模型回归。

报告标题或 `scope` 字段也可能滞后。先核对实际资源哈希，再修正文案并保留原始记录；不能用标题中的版本号替代资产身份。远程验收应交付可直接查看的原生图片或录屏，不能只给开发机本地地址。
