# 案例：重复播放后换主题，动作意图消失

[返回目录](../README.md) · [教学示例](../examples/semantic-handoff.mjs)

暗夜动作重播先退出到 idle，再开始同一动作。旧主题包装层在 idle 通知时清掉待交接意图，却没有在动作重新开始时恢复它。因此随后切日常时，只接到了 idle。这个故障与纹理、脸层或动作节奏无关。

修复规则是：维护每个渲染侧的实际动作；只允许当前可见侧的事件修改对外动作意图；非 idle 开始事件重新确认意图；idle 结束事件只清理它实际结束的动作。隐藏侧过期回调不能覆盖当前侧。资源加载则另外使用版本令牌，以最后请求为准。两套责任不能互相替代。

同一动作 ID 只代表业务意图，不代表相同秒数/相同参数。两套角色有不同的起势、停留和返回，应在转场遮挡与资源就绪条件下进入目标表演，不强行复制一套参数到另一套模型。

历史本地检查覆盖八动作 × 两方向 × 15%/45%/85% 三阶段，共 48 个场景，加 6 个快速反向和 3 个重复播放，合计 57。另有替身加载器检查首次加载未结束和过期动作加载完成。真实渲染检查与状态机测试分开记录。

这些检查补充了原仓库的异步外观提交案例，没有推翻请求版本机制。公开示例只演示动作通知交接，不实现转场计时、资源加载或 GPU 渲染。产品还应独立处理加载失败、取消、异常恢复、页面暂停和资源释放。
