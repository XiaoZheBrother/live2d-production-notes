# 案例：侧脸通过数值检查，为什么仍然不像底图

[返回目录](../README.md) · [头部绑定](../docs/03-head-and-eyes.md)

## 症状与基线

暗夜夸奖的嘴形已接近确认稿，用户希望移开视线时脸也像分镜一样撇过去。最初只有正脸横移，后续增加透视形变后，又出现脸被拉扯、眼睛不像的问题。必须保留的是已确认唇线、五官画法、肤色、身体视角与动作节奏。

## 被否定的候选

历史 v5 使用连续侧脸关键形，并叠加已有朝向与眼部形变。检查显示它没有新增异常翻折，但用户拒绝了可见结果。记录必须同时保留“数值通过”和“视觉失败”；前者不能覆盖后者。

这也不证明所有连续变形都不可用。它证明的是：**当前原画、拓扑、参数叠加与目标角度的组合，没有达到本次视觉目标。**

## 后续采用的制作路线

1. 先生成正面、中间角度与最终撇脸三张参考，保持身体机位，交由用户确认。
2. 各角度使用对应原画像素与独立 UV，放在同一个原生模型中；保留已确认的眼睛、嘴和颊部画法。
3. 配准轮廓、眼角、虹膜、鼻尖、嘴角、发夹与颈部。先检查每个关键角度，再检查过渡。
4. 整理旧朝向和专用转脸的参数所有权，防止重复施加透视。
5. 眼睛后面的皮肤、闭眼等不可见部分单独补全；旧脸与新脸的覆盖时机、原生透明度和绘制顺序一起校准。
6. 重新导出，在目标 Core 中采样转脸、眨眼和提前退出；保留同角度原生截图供视觉确认。

这不是将三张完整角色图片依次播放，也不是三个完整运行时模型。每个角度仍然需要可动部件、遮罩和可编辑关键形。

## 两个容易漏掉的技术点

**透明度互补不保证皮肤不透底。** 简化到普通 source-over 合成，两个全不透明素材分别取 `a` 和 `1-a`，合成 Alpha 为 `a + (1-a)²`，当 `a=0.5` 时只有 0.75。更何况眼睛、发丝本身还有透明边缘。需要连续的皮肤覆盖和合适的交接时机，而不是仅让两个权重相加等于一。

**分段映射边界要反映到拓扑。** 若三角形跨过使用不同映射的两个区域，单纯增加整体网格密度仍可能发生异常拉扯。项目候选需要沿实际映射边界细分，再检查全部中间值。这个修法针对分段映射，不是所有 Cubism 模型都应套用的规则。

## 证据与限制

v6 的历史报告包含 367 个动作采样、25 个转脸与眨眼组合、244 个退出检查项；关键角度配准误差小于 0.000075 模型像素。后者是坐标误差，**不是视觉相似度**，也不是普遍应追求的美术精度。

最终领口修补后有编辑器截图与数值记录，但对应浏览器复验存在受阻记录，不能沿用前一个候选的浏览器结果宣称最终版本全通过。完整取代关系与来源见[后续证据快照](../references/night-character-evidence.md)。

## 迁移到其他角色时

先尝试目标幅度内的常规变形器与合理部件分离；若必须明显改变远近眼、脸颊遮挡或嘴鼻画法，且连续变形始终不能还原参考，再评估角度专用素材。把多出的图集、编辑内存、闭眼补全与交接检查一起计入成本。
