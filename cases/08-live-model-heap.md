# 案例：主题切回后丢脸，参数在变化但角色不动

[返回目录](../README.md) · [原理示例](../examples/heap-views.mjs)

## 可复现的差别

分别加载日常、暗夜并播放都正常；保留日常，先后加载暗夜待机与成功，切回日常后，跟随失效，动作隐藏待机脸却没显示动作脸。纹理文件、动作参数和数组长度都看起来正常。

真实回归定位于固定 Cubism Core 5.1 asm.js 构建的共享堆增长：新分配将内存复制到新 ArrayBuffer，而已创建模型的 TypedArray 仍引用旧 buffer。旧数组非空、数值有限、不会抛异常，却无法读写引擎当前数据。左右朝向参数对应的嘴部最大位移从约 0.02536 变为 0。

不能把它直接写成所有 WASM/所有 Core 版本的相同故障。WASM 的 memory.grow 与具体绑定层也有各自视图行为，需要检查当前运行构建。这里确认的是项目使用的 asm.js 复制扩容路径。

## 项目修复及移植边界

每次 MOC/model 分配结束后同步刷新全部存活实例的 Parameters、Parts、Drawables 数组；保留旧容器对象，避免渲染闭包继续持有旧 drawables。分配失败也可能已扩容，刷新不能仅放在成功路径。释放操作幂等并移除登记。

该修复依赖固定 Core 构建的内部指针和构造器，不能作为通用 SDK API 推荐。先核对官方生命周期接口和当前版本，再隔离兼容适配；不要让学习者直接复制私有字段访问。提前扩大堆只能延后触发，不能证明任何规模都安全。

## 回归不能只测数值合法

- 常驻模型加当前/下一模型同时存在，明确断言测试期间 buffer 身份确实改变。
- 扩容前后比较日常各动作多个时点的全顶点和透明度；保留当前暗夜实例也接受检查。
- 参数左右切换后，目标可见网格必须有真实差异；不能只检查参数值被赋过。
- 加载两轮、失败加载、幂等释放与清空暗夜后继续使用日常。
- 产品里正常速度走暗夜动作→切日常→播放日常动作→返回→鼠标跟随。

公开[示例及测试](../examples/heap-views.test.mjs)用合成堆演示“旧数组仍有长度却过期”和“容器身份保留”；它不包含 Core，不代替真实 MOC 测试。
