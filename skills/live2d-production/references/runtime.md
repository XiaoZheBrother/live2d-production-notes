# 多角色、主题与运行时故障

业务意图 ID、每侧实际播放状态、外观配置与有效主题分开维护。同一 ID 可对应不同表演/时长；新角色未完成的动作要显式缺失或使用已接受的回退。不要复制另一角色的参数值假装兼容。

## 主题交接

- 新请求带版本；慢旧加载不能覆盖快新请求。失败保留完整旧模型，释放过期资源。
- 资源就绪与转场遮挡分别处理。不要让主题动画完成意味着模型一定加载完成。
- 当前可见侧的非 idle 开始事件恢复语义动作；idle 只结束对应动作。隐藏侧旧回调不能清掉新意图。
- 重播可能出现 action→idle→同 action，必须测试这个边界及其间换主题。
- 临时卸载/取消完成后恢复眼/头/身跟随；参数响应与实际顶点都检查。

## 丢脸/冻结诊断

先验证资产选择、层透明度与参数是否真实作用于当前 Drawable。若分别播放正常、多模型并存才坏，检查模型生命周期与共享内存。

固定 Core 5.1 asm.js 构建曾扩容复制堆，旧 TypedArray 仍非空却指向旧 buffer。项目用分配后刷新所有存活模型视图解决；渲染器闭包保留的容器身份也要保持。分配失败仍可能扩容；释放须幂等。

这不是所有 SDK 的通用 API。先查看当前构建/官方封装，隔离版本兼容层，不盲目访问内部指针。预留堆只能缓解某一预算，不能保证任意资产规模。测试明确触发扩容，旧新实例都要更新；没有触发目标路径的“通过”不算回归覆盖。

## 最小交接矩阵

对每个有限动作 × 两个方向 × 准备/中段/收尾切换；再测转场初期与显现期快速反向、重播后切换、首次加载未完成反向、过期动作加载结束、加载失败。每次最终检查最后请求的主题、动作状态、脸部可见、跟随与资源数量。

按需加载和纹理哈希去重能控制资源，但源包总字节、解码后纹理内存、CPU 堆和 GPU 资源不是同一指标。先测实际宿主预算再谈公网交付；只有本地预览不能宣称上线性能通过。
