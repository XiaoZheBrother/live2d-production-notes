# 原生制作与有限动作

## 保真修复

局部修复前固定嘴形、脸缘、手臂轨迹、比例、袖型、时长等保护项。肩袖接缝不自然时先核对连续布料和共享边界，避免“优化”整条手臂导致扭转。前臂与手围绕稳定关节运动，检查中间插值是否缩短或剪切。

抱胸/持书：明确每只手的可见部位和接触物。不要用缩手或整层后移假造藏手；用接触处局部袖料遮挡，同时留可读的腕与掌根。起势、中段、落点都保持比例。书本淡出后要有完整空手素材，返回时书/手遮挡关系也要恢复。

脸、眉眼、嘴的身份要同角度核对；表情局部贴图若有矩形色差，检查是否叠了两块不同肤色的脸皮。冷艳、困倦、得意、羞怯可能只差眼裂与嘴角；不只调一个眼开度。

## 参数所有权

待机是常驻状态：鼠标眼/头/身跟随、眨眼、呼吸和发尾轻摆持续工作。有限动作临时接管需要的参数，不要让两套透视/表情/物理重复写同一效果。

动作时间、物理/自然动态时间、主题转场时间分开。动作加速不能放大眨眼和发尾速度。暂停恢复要处理过大时间步与残余速度。

在制作前声明支持域。例如某专用侧脸要求表情层先建立，则返回顺序是先回到支持朝向，再退出表情，最后交还跟随；阈值按模型确定。取消应捕获当前姿态，检查首帧连续与完整退出路径，不从固定退场起点跳回。手书接触、眨眼和物理也属于组合约束。

## 原生与宿主

分清编辑源、导出 MOC、标准 motion/expression/physics 文件、宿主控制脚本。只有网页修了排序/遮罩/姿态，不能声称原生工程已修。编辑后按目标版本正式保存、导出并用目标 Core 读取实际 Drawable。

自定义渲染器若使用专用遮罩几何，分别核对 stencil 与颜色通道；透明度为零不一定意味着该遮罩应被跳过，但需遵守具体引擎契约，不能全局套用。

没有编辑器或缺少导出能力时，保留候选源、补图、参数方案与未完成清单。不能把关键形 JSON 或浏览器动画重命名为原生交付。
