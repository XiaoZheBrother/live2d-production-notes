# Live2D 制作与精修

把用户确认的角色做成可验证的可动资产，或修复已有模型。优先保护已接受的脸型、表情、动作和节奏，区分素材、原生模型、宿主与发布层的问题。

这个包包含流程、检查参考与只读脚本，不包含图像生成器、MOC 编译器、Cubism Core、角色资产或商业项目构建器。使用当前环境实际可用且获授权的图像工具、Editor、SDK 和代码工具；缺少能力时交付明确的中间产物，不伪称完成原生绑定。

## 定位任务

先读取当前工程说明、资产清单和最近确认，确认：目标宿主，源工程是否可编辑，基线/候选路径，获准修改的部位，必须保留的内容，目标幅度与交付要求。已有答案不重复询问。确认原画不等于确认每个后续动态候选；已授权绑定的任务也无需重新要一次绑定许可。

## 执行原则

1. **固定基线。** 候选另存；记录源图、源工程、运行模型、纹理、动作和宿主版本。改局部时列出保护项，用可比较数据核对，不以文件名 final 判断接受状态。
2. **先找故障层。** 缺角先查原像素、网格/UV、蒙版、层级；不动先查当前可见网格响应和模型生命周期。问题在宿主时，不先重画脸或改原生动作。
3. **用最小有信息量的试验。** 头发先一束，关节先一段，表情先同角度。静态通过才检查曝光、插值和组合；一次失败要更新原因，不只是继续堆补层或平滑。
4. **保护身份与语义。** 不为便于绑定擅自把长发改短、全身裁半身、露出额头或改变身体机位。动作要在实际显示尺寸读得懂；成功、夸奖与鼓励的主体可能不同。
5. **分清证据。** 回贴原图的低误差不证明生成式拆层准确；零翻折不证明不拉扯；原生身体叠网页候选层不等于新 MOC；导出通过不等于用户接受或上线。
6. **按授权交付。** 用户要求先确认底图时，停在可查看候选；已经授权实现时，完成实现及自查再交付。用户允许缩小范围后可回退稳定版，不能把减小幅度描述为原目标已完成。

若同一缺陷反复出现且本次试验没有新证据，保留失败输入、参数、结果与原因，换有依据的诊断分支或报告具体缺口。不要覆盖可靠基线，也不要承诺无界自动迭代一定成功。

## 环境与输出契约

在大量出图前确认图像编辑能力、目标 Editor/SDK 版本、原生导出方式、运行宿主和资源预算。使用项目已有工具链；只为当前阶段准备所需依赖。敏感素材若需外传或下载/运行新的模型，按用户授权和宿主规则处理，不把本 skill 当作额外授权。

本工作流优先保留可编辑源工程，经用户要求的原生工具保存导出。仅有运行 MOC 的路线可以按约定交付，但必须标明无可编辑 CMO；不能把一个能读的 MOC 描述为完成 Editor 往返。

已有 `model3.json` 时可运行：

```bash
python <skill-dir>/scripts/inspect_package.py <model-dir>/character.model3.json
```

脚本只读：检查文件引用/目录边界、必需 MOC/纹理、可选动作/表情等引用，输出 SHA-256 与缺失项。Python 3.10+，无第三方依赖。它**不解析或执行 MOC**，不验证 Core 兼容、眨眼、动作绑定或美术效果。输出到包目录外，避免污染资产。

## 收尾

交付实际原生/宿主渲染的全身与风险部位对照；用户远程访问时直接附图片/录像，不能只给开发机地址。报告本轮改变、保护项、验证对象/范围、失败或未测内容，以及当前处于候选、原生导出、用户接受、本地接入还是发布阶段。
